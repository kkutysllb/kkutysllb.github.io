本项目是一个纯静态单页站点，采用「YAML 数据 + 单 HTML」架构，无需编译工具链。构建与发布由以下三部分构成：

### 1. 本地开发
- 通过 `package.json` 的 npm scripts 启动 Python 内置 HTTP 服务器（端口 4173）进行本地预览：
  - `npm run dev` / `npm run preview`
- 无打包、无转译、无依赖安装步骤，直接打开 `index.html` 即可。

### 2. 数据同步 CI（GitHub Actions）
- 工作流 `.github/workflows/sync-releases.yml` 每 6 小时定时触发，也可手动 `workflow_dispatch` 触发。
- 读取根目录 `repos.txt`（格式：`<releases_file> <owner/repo>`），对每个仓库调用 GitHub API `repos/{owner}/{repo}/releases/latest`，裁剪字段后写入 `data/releases/<releases_file>.json`。
- 若某仓库没有 release，则保留占位文件 `{"_placeholder":true,"assets":[]}`，保证前端容错加载。
- 仅当 `data/releases/` 有变更时才 commit 并 push，commit message 为 `chore(releases): sync from GitHub Releases`。
- 使用 `GH_TOKEN=${{ secrets.GITHUB_TOKEN }}` 认证，权限为 `contents: write`。

### 3. 部署配置（Vercel）
- 根目录 `vercel.json` 声明 Vercel 行为：
  - `cleanUrls: true`、`trailingSlash: false` 控制 URL 风格。
  - 为 `/data/releases/(.*)` 设置缓存头 `Cache-Control: public, max-age=3600, must-revalidate`。
  - 为所有资源附加安全响应头：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`。
- 由于是纯静态站点，Vercel 自动检测并部署，无需自定义 build 命令。

### 关键约定
- **数据驱动**：页面结构完全由 `data/projects.yml` 和 `data/releases/*.json` 驱动，新增产品只需修改 YAML 并在 `repos.txt` 中注册对应仓库。
- **Release 文件命名**：`repos.txt` 中的第一列即为 `data/releases/` 下的 JSON 文件名，需与 YAML 中 `channels[].releases_file` 保持一致。
- **平台匹配**：前端通过 `file_glob` glob 模式匹配 release asset 名称，支持 `*` 通配符。
- **主题持久化**：用户主题偏好保存在 `localStorage.krelease-theme`，默认 dark。

### 开发者注意事项
- 修改 `data/projects.yml` 或新增产品后，无需重新构建；CI 会在下次定时任务时拉取最新 release。
- 如需立即生效，可手动触发 workflow_dispatch。
- 本地调试可直接用浏览器打开 `index.html`，或使用 `npm run dev` 启动服务。
